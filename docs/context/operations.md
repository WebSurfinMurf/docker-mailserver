# Operations

## Restart semantics — mail-edge-wg / mailserver coupling
- [IMPLEMENTED] Both containers are `restart: unless-stopped` and start in order via
  `depends_on: condition: service_healthy` — this only orders *startup*, not ongoing recovery.
- Restarting `mail-edge-wg` alone **destroys the shared network namespace**. `mailserver`
  keeps running inside the now-orphaned netns rather than being restarted by Docker.
- `mailserver`'s healthcheck checks for a live `wg0` inside its netns (not just an open port)
  specifically to catch this — but detection ≠ recovery. **Manually restart `mailserver`**
  after any `mail-edge-wg` restart.

## Host reboot
- [IMPLEMENTED] Both containers come back on host reboot via `restart: unless-stopped` (no
  host-level `wg-quick@wg0` systemd unit — this host has no passwordless sudo for an
  autonomous worker to install one).

## Secrets
- `~/projects/secrets/mail-edge-wg.conf` (mode 600) — WireGuard peer config, generated by
  `~/projects/aws/mail-edge/`. `AllowedIPs = 10.77.0.0/24` — scoped to the tunnel subnet only,
  so `mailserver`'s general internet egress (e.g. SendGrid relay) is unaffected.
- `~/projects/secrets/docker-mailserver.env` — main env config (unchanged by this work).

## DKIM key material
- `config/opendkim/keys/` contains a private key readable only by `root` inside the container
  (perm-denied for the `administrator` user). [IMPLEMENTED] `.gitignore`d as `config/opendkim/`
  — never commit private key material.
